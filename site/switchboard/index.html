Why a second model needs more than an API call

For some jobs a second model helps: reading a 300-page spec, checking what changed in a library last month, running research tracks in parallel, or getting an independent review before you merge. Wiring one up sounds easy until it breaks:

  • the model ID you hard-coded gets retired and starts returning 404;
  • "high demand" 503s stall your agent for minutes;
  • a retry loop on a quota error burns the rest of your daily allowance;
  • a thinking model spends its whole output budget on reasoning and returns an empty string;
  • your agent helpfully runs echo $GEMINI_API_KEY to "check it's set".

Switchboard handles each of these.

FAQ

Does it work without Gemini?

Yes. Without a key, or when your quota runs out, the commands say Gemini is unavailable and Claude carries on with its own tools.

Will it run up my Gemini bill?

Every call is logged with token counts (python -m switchboard usage). Concurrency is capped, retries are bounded, and quota errors stop calls instead of retrying. Set billing alerts in Google Cloud as well.

Does the hook make key leaks impossible?

No. It blocks the common ways an agent exposes a key, which makes it a seatbelt, not a vault. The included docs explain what it covers and what to layer with it.
